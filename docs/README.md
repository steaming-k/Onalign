# Onalign

**흩어진 의견을, 하나의 방향으로.**

회의에서 의견은 모이지만 결정과 다음 행동으로 이어지지 않는다는 문제에서 출발한 퍼실리테이션 보드다. 의견 작성 → 문제 정리 → 우선순위 투표 → 회고(KPT) → 문서화까지, 한 프로젝트 안에서 흐름이 끊기지 않게 만드는 걸 목표로 한다.

🔗 **Live Demo** : [onalign.vercel.app](https://onalign.vercel.app)

## 이 프로젝트가 존재하는 이유

캠프 아이디어 회의에서 '문제 정의' 단계에 가장 많은 시간을 쓰고, 그마저도 서로 다른 말로 같은 문제를 가리키는 걸 못 알아채 회의가 길어지는 걸 직접 관찰했다. 개인 경험을 그대로 문제로 확정하지 않기 위해, 프로젝트 종료 후 작성된 11개 팀의 KPT 회고를 검토해 같은 패턴이 팀을 바꿔도 반복되는지 확인했다.

회의의 문제는 의견이 부족한 것이 아니라, **판단의 이유가 남지 않아 같은 논의를 다시 반복하는 데 있었다.** Onalign은 이 지점 하나를 겨냥한다 — 아이디어를 낸 시점의 우선순위를, 종료 시점의 회고에서 다시 확인할 수 있게 잇는 것.

## 스크린샷

> 실제 화면 캡처를 이 자리에 넣는다 (랜딩 / 의견 작성 / 우선순위 투표 / 문서 내보내기 등, 가로형 1200×700 권장)

## 핵심 흐름

| 단계 | 내용 |
|---|---|
| 1. 의견 작성 | 참여자 전원이 동시에 포스트잇을 작성하고, 같은 주제끼리 병합한다 |
| 2. 문제 정리 | 병합된 의견 중 '문제'로 표시된 것만 상단에 남긴다 |
| 3. 우선순위 투표 | 인당 투표권 한도 안에서 가장 시급한 문제에 투표한다 |
| 4. 회고 (KPT) | 프로젝트가 끝나면, 우선순위에 올랐던 문제가 실제로 해결됐는지 각자 되짚는다 |
| 5. 문서화 | 의견·문제·투표·회고·회의 녹취록을 문서 하나로 모아 docx / 마크다운 / PDF로 내보내거나, 프롬프트로 뽑아 평소 쓰는 AI에 이어 넘긴다 |

## 기술 스택

- **Frontend** : Vite + React
- **Backend / DB** : Supabase (Postgres, Auth, RLS)
- **Auth** : Google OAuth (PKCE, 전체 페이지 리다이렉트)
- **Deploy** : Vercel
- **문서 생성** : docx 조립, jsPDF(화면 캡처 기반), Web Speech API(브라우저 내장 음성 인식)
- **회의 오디오 캡처 (설계 확정, 구현 예정)** : `getUserMedia`(마이크) + `getDisplayMedia`(탭/화면 오디오)를 Web Audio API로 혼합해 단일 트랙 생성 — 상세는 아래 '판단을 수정한 기록'과 '아직 열려 있는 문제' 참고

## 설계 원칙

이 프로젝트를 관통하는 원칙은 하나다 — **원본은 하나이고, 여러 화면은 그 데이터를 다른 관점으로 표시만 한다.** 문제 표시·투표·해결 여부·회고 완료·리더 소유권이 전부 이 패턴을 따른다. 유일한 예외는 문서 스냅샷이다 — '그 시점 그대로 고정'이 존재 이유라, 계산 결과를 통째로 복사해서 별도로 저장한다.

그 위에 두 가지 원칙을 실사용자 테스트를 거치며 추가로 명문화했다.

- **개인 화면 상태와 공유 데이터를 분리한다.** '지금 보는 탭'처럼 개인 UI 상태를 폴링되는 공유 데이터(board JSON)에 넣으면, 한 사람이 탭을 넘길 때 다른 참여자 화면도 같이 넘어가는 버그가 생긴다.
- **에러와 '확인된 부재'를 구분한다.** `maybeSingle()`은 네트워크 에러와 '그 행이 실제로 없음'을 둘 다 `data: null`로 뭉뚱그린다. 이 둘을 구분하지 않으면 삭제된 프로젝트 링크가 무한 로딩으로 보이는 것과, 있어야 할 프로젝트가 목록에서 영영 안 보이는 것을 같은 코드로 처리하게 된다.

권한은 항상 두 겹으로 강제한다. UI에서 버튼을 숨기는 것만으로는 API 직접 호출을 막지 못하기 때문에, 오너 전용 기능은 Supabase RLS 또는 트리거로 한 번 더 검사한다. `projects` 테이블의 `instructions`·`votes_per_user`처럼 컬럼 단위 보호가 필요한 경우는 RLS가 행 단위로만 동작하는 한계를 트리거로 보완했다.

회의 오디오 캡처 확장을 설계하면서 원칙이 하나 더 늘었다 — **웹 표준 API의 불확실성 자체를 설계에 넣는다.** 마이크+탭 오디오를 하나로 섞은 트랙에 브라우저 내장 음성 인식(`SpeechRecognition.start(track)`)을 걸 수 있는지는 MDN도 "Limited availability"로만 표시할 뿐, 사전에 지원 여부를 확인할 표준 방법이 없다. 이 불확실성을 없애고 나서 설계하는 대신, 실패할 가능성을 전제로 결과를 '녹음 파일 저장(신뢰도 높음)'과 '실시간 텍스트 변환(신뢰도 불확실)'으로 분리했다 — 실시간 변환이 실패해도 오디오 파일에는 양쪽 소리가 그대로 남아, 최악의 경우에도 지금보다 나빠지지 않는 구조다.

## 판단을 수정한 기록

30개가 넘는 버전은 기능을 늘린 기록이 아니라, 근거가 바뀔 때마다 판단을 다시 쓴 기록이다.

| Before | 계기 | After |
|---|---|---|
| 참여자는 로그인 없이 이름만 입력 | 프로젝트 소유권 · 권한 · 데이터 구조가 실제 협업 흐름과 맞지 않음 | 전원 구글 로그인 필수 |
| HTML 다운로드 | 주변 사용자 테스트 결과, 한글 문서 환경에서는 Word 계열 사용성이 더 납득 가능하다는 피드백 | docx 내보내기 |
| AI 자동 요약 기능 | 생성 결과를 서비스가 확정하는 구조보다 사용자 통제권을 우선하기로 결정 | 프롬프트 추출(콘텐츠를 조립해 사용자가 쓰는 AI에 넘김) |
| 기능 단위 테스트 | 개별 기능은 동작해도 화면 전환 · 공유 범위 · 동기화가 어긋남 | 사용자 흐름 단위 QA로 확장 |
| '로컬에서 수정 완료' = 배포 완료로 간주 | 같은 버그가 여러 라운드에 걸쳐 재발 — 원인은 로컬과 원격 저장소의 갈래 분리 | '로컬 완성'과 '배포 검증 완료'를 서로 다른 상태로 관리 |
| 회의 녹음을 '녹음 후 변환 버튼' 배치 처리로 구현하려던 안 | 무료 Web Speech API는 살아 있는 오디오 트랙이 있어야 동작해서, 저장된 파일을 재생해 재캡처하는 우회가 필요해지고 그 우회 API 역시 지원이 불확실함을 확인 | 배치 처리 폐기, 마이크+탭 오디오를 실시간으로 섞은 트랙에 바로 인식을 거는 구조로 변경 |

가장 크게 뒤집은 결정은 '로그인 없이 참여'다. 참여 마찰을 낮춘다는 초기 차별점이었지만, 소유권과 권한 구조가 필요해지는 시점에서 전제 자체를 바꿨다. 이후 STEP 배너 편집·투표권 조정·프로젝트 삭제 같은 기능들은 이 전환 위에서 리더/팀원 권한으로 다시 설계했다.

## 폴더 구조

```
Onalign/
├── src/
│   ├── components/       # 화면 단위 컴포넌트 (의견 작성, 문제 정리, 투표, 회고, 문서)
│   ├── hooks/             # Supabase 폴링, 인증 상태, 권한 체크
│   └── lib/               # Supabase 클라이언트, docx/PDF 조립 로직
├── supabase/
│   └── schema.sql         # 테이블, RLS 정책, 트리거
├── public/
│   ├── index.html         # 랜딩페이지
│   ├── terms.html
│   └── privacy.html
└── vite.config.js
```

> 실제 저장소 구조에 맞춰 위 트리를 조정한다.

## 로컬 실행

```bash
git clone https://github.com/<your-repo>/onalign.git
cd onalign
npm install

# .env.local
VITE_SUPABASE_URL=your-supabase-url
VITE_SUPABASE_ANON_KEY=your-anon-key

npm run dev
```

Supabase 프로젝트를 새로 만드는 경우 `supabase/schema.sql`을 SQL Editor에서 한 번 실행한다. Google OAuth는 Supabase Auth 설정에서 클라이언트 ID·시크릿을 등록해야 한다.

## 배포

Vercel에 연결돼 있으며 `main` 브랜치 push 시 자동 배포된다. 정적 페이지(`terms.html`, `privacy.html`)를 추가할 때는 `vite.config.js`의 빌드 입력에 반드시 등록해야 한다 — 등록하지 않으면 로컬에서는 보이지만 배포에는 404로 빠진다.

## 아직 열려 있는 문제

- 5~8인 소규모 팀에서도 '동시 작성'이 실제로 효과가 있는지는 학계에서도 결론이 갈린다
- 회고가 실제로 팀에 도움이 되는지는 실증 연구 자체가 얇다
- 실명 투표는 사후 논의 가능성을 우선한 트레이드오프이며, 편향 위험을 인지하고 감수한 결정이다
- 회의 오디오 캡처 확장은 설계만 확정됐고 구현 전이다. 가장 큰 미검증 항목은 혼합 트랙에 대한 실시간 음성 인식 동작 여부이며, 그 외에도 브라우저별 지원 범위 확인·탭 오디오 공유 체크박스 안내 카피·헤드폰 미착용 시 에코 경고 등 6가지를 구현 전에 확인할 계획이다
